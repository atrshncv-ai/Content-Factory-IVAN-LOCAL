# 08 — Тестовый контур Mac + Node 1 и приёмка MVP

**What to build:** Воспроизводимый тестовый контур, где Hermes-оркестратор
работает на Mac разработчика, а ComfyUI — на клиентском Windows Node 1 через
Tailscale. Контур подтверждается двумя последовательными пользовательскими
циклами, восстановлением процессов и актуальным GitHub-репозиторием.

**Blocked by:** 07 — Круглосуточная эксплуатация и сохранность.

**Status:** ready-for-agent

- [ ] Mac разработчика запускает Hermes Gateway, Telegram и cron без ручного запуска каждого отдельного процесса.
- [ ] Node 1 запускает Tailscale и ComfyUI с утверждённым API workflow без ручной команды.
- [ ] Mac и клиентский Node 1 находятся в одном tailnet; оркестратор проходит трёхуровневую проверку Node 1.
- [ ] `.env.example` перечисляет только имена требуемых параметров; реальные токены, ключи, ID и абсолютные пути не коммитятся.
- [ ] Acceptance A проходит подряд: `/new_video` -> фото и идея -> Hermes -> ComfyUI -> Telegram -> «Принять», с измеренным временем.
- [ ] Acceptance B проходит подряд: `/plan` -> анализ -> правка/замена -> утверждение -> фото -> ближайшее расписание -> ComfyUI -> Telegram.
- [ ] После перезапуска процессов тестового контура состояние сохраняется и приходит уведомление о восстановлении.
- [ ] Полный pytest и mypy проходят, граф зависимостей обновлён, документы описывают фактическую MVP-архитектуру и команды запуска.
- [ ] Все завершённые тикеты закоммичены и отправлены в `atrshncv-design/Content-Factory-IVAN-LOCAL`.
- [ ] Установка Hermes на отдельный Windows-ПК клиента явно оставлена следующим этапом после успешных тестов.
