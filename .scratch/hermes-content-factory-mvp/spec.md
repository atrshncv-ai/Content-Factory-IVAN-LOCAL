# Hermes Content Factory MVP

**Status:** ready-for-agent

## Problem Statement

Клиенту нужен работающий на двух его Windows 11 ПК контент-завод, который
превращает идею и фотографию в готовое видео без ручного запуска терминалов.
Сейчас кодовая база подтверждает только диагностический путь
«Telegram-фото -> Python-воркер -> ComfyUI -> Telegram» и содержит устаревшие
агенты планирования, оценки и публикации. Она не реализует согласованный
пользовательский продукт на Hermes: профиль бренда, недельный план, утверждение
карточек, расписание, очередь, восстановление и управление через Telegram.

MVP должен доказать надёжность всего конвейера на клиентском оборудовании.
Художественное качество отдельной генерации оценивает человек; автоматическая
публикация и идеальное клонирование лица или голоса не должны блокировать сдачу.

## Solution

На текущем этапе Node 2 работает на Mac разработчика: там запускается Hermes
Agent с одним Telegram-ботом. Hermes выступает оркестратором и запускает скрытых
подчинённых агентов:
веб-парсера, стратега, сценариста и промпт-инженера. Интеллект и пользовательский
диалог остаются в Hermes, а минимальный детерминированный мост управляет
техническим журналом задач и ComfyUI.

Node 1 работает как круглосуточный GPU-узел с ComfyUI. Узлы соединены одним
Tailscale tailnet. Мост загружает фотографию, подставляет разрешённые входы в
версионированный API workflow, ставит ровно одну генерацию в очередь, опрашивает
историю и временно скачивает MP4 на Node 2 для отправки в Telegram. Оригинальные
фото и видео постоянно остаются на Node 1.

Пользователь управляет MVP только через Telegram-команды `/setup`, `/plan`,
`/new_video`, `/status` и `/cancel`. Агентские запуски событийные и одношаговые:
каждый cron-тик читает сохранённое состояние, выполняет один переход Kanban,
записывает результат и завершается с чистым контекстом.

   изменить профиль.

   если дал конкретную идею, чтобы быстро запустить разовую генерацию.

## Implementation Decisions

- На этапе разработки и приёмочных тестов Node 2 работает на Mac разработчика.
  Установка Hermes на клиентский Windows 11 ПК выполняется после подтверждения
  MVP и не входит в текущую реализацию.
- Один Telegram-бот представляет оркестратора. Подчинённые агенты скрыты от
  пользователя.
- Парсер, стратег, сценарист и промпт-инженер реализуются как Hermes agents/skills,
  а не как новый набор постоянно работающих Python-демонов.
- Парсер использует открытый веб как основной путь. Прямой Instagram остаётся
  экспериментальным best-effort сценарием с ручным входом пользователя.
- ChatPlace/Viral исследуется отдельно и не блокирует приёмку.
- Профиль бренда и планы хранятся структурированно в workspace Hermes. Отдельная
  папка базы знаний может быть пустой на тестах, но доступна агентам.
- SQLite остаётся узким техническим журналом заданий ComfyUI, попыток, времени,
  результата и аудита значимых действий.
- Telegram-кнопки отправляются одноразовым gateway как `InlineKeyboardMarkup`;
  проверка карточек последовательная, callback подтверждается и выполняет один
  сохранённый переход. Постоянный polling-сервис не нужен.
- Cron запускает свежие одношаговые сессии. Главный процесс не содержит
  бесконечных агентских циклов.
- Мост ComfyUI детерминирован: health-check, загрузка фото, патч разрешённых
  входов workflow, постановка в очередь, опрос истории, отмена, скачивание
  результата.
- Результаты получаются через ComfyUI API по Tailscale; SMB и Google Drive для
  MVP не требуются.
- Очередь непредвытесняющая: один активный рендер; просроченные и ближайшие
  плановые задачи выше ручных, внутри уровня применяется FIFO.
- Таймаут попытки — 60 минут. Разрешена одна автоматическая повторная попытка.
- Видео считается доставляемым, если файл существует, имеет MP4-контейнер и
  Telegram принимает его. Автоматические `ffprobe`, Vision QC и оценка звука не
  выполняются.
- OpenCode Zen с бесплатной моделью — основной интеллект. Два ключа выбираются
  последовательно только при rate-limit/quota; значения секретов существуют
  только в окружении.
- Все директории, адреса, Telegram ID, токены и ключи задаются окружением; пути и
  секреты не хардкодятся.
- Старые Python Parser/Planner/Prompter/Evaluator/Publisher не участвуют в
  пользовательском MVP-маршруте. Рабочие части Comfy renderer/poller/SQLite
  переиспользуются или упрощаются.
- Каждая завершённая задача разработки фиксируется отдельным коммитом и
  отправляется в GitHub-репозиторий `atrshncv-design/Content-Factory-IVAN-LOCAL`.
- На текущем этапе устанавливается Node 1 на клиентском Windows-ПК, а Node 2
  запускается на Mac разработчика. Механизм последующих продуктовых обновлений
  после сдачи не входит в MVP.

## Testing Decisions

- Главный автоматический шов — внешний пользовательский переход:
  Telegram-событие -> сохранённое состояние -> команда мосту ComfyUI ->
  результат/уведомление Telegram.
- В автоматических тестах Hermes, Telegram, часы и ComfyUI заменяются
  контролируемыми адаптерами; проверяется наблюдаемое состояние и сообщения, а
  не внутренние вызовы отдельных агентов.
- Существующие тесты одношагового `MVPWorker`, workflow patching, поллера,
  SQLite-миграций и конфигурации используются как prior art.
- Контрактные тесты покрывают команды, allowlist, идемпотентность callback,
  расписание, приоритет очереди, таймаут/повтор, восстановление, очистку и
  отсутствие секретов в логах.
- Реальный acceptance A на связке Mac Node 2 + клиентский Windows Node 1:
  `/new_video` -> фото и идея -> Hermes создаёт сценарий и промпт -> Node 1
  генерирует вертикальное видео не короче целевых 10 секунд со звуком -> MP4
  приходит в Telegram -> пользователь принимает.
- Реальный acceptance B:
  `/plan` -> веб-анализ -> три карточки -> правка первой, замена второй ->
  утверждение -> фото -> одна карточка переносится на ближайшее время ->
  автоматический рендер -> MP4 приходит в Telegram.
- Оба сценария выполняются подряд на Mac разработчика и клиентском Node 1.
  Проверяется перезапуск процессов текущего тестового контура и восстановление
  сохранённого состояния.
- Перед каждым завершённым тикетом обязательны релевантные тесты и `mypy`.
  Полный набор запускается в финале.

## Out of Scope

- Автоматическая публикация в Instagram, подписи и хэштеги.
- Автоматическая генерация стартового изображения или лица.
- Клонирование голоса клиента, точные ударения и специализированный lip-sync.
- Гарантия художественного реализма или автоматический Vision-контроль видео.
- Встроенные субтитры.
- Telegram-каталог и поиск по архиву.
- Веб-панель управления.
- Google Drive, SMB и облачные резервные копии.
- Автоматическое сжатие слишком большого видео.
- Telegram-команды удаления материалов или смены workflow.
- Обязательная интеграция ChatPlace/Viral.
- Гарантированный прямой парсинг Instagram.
- Мультибренд и сеть аккаунтов.
- Самообновление и production-сопровождение.
- Установка Hermes-оркестратора на отдельный Windows-ПК клиента.
- Любые Production-функции из клиентского ТЗ, не перечисленные в Solution.

## Further Notes

- Более свежие решения интервью имеют приоритет над устаревшими корневыми
  документами и противоречащим им пунктом клиентского ТЗ о точном клонировании
  лица и голоса в MVP.
- Текущий репозиторий уже имеет проверенный диагностический результат:
  1-секундный ролик 512 px был получен примерно за 110 секунд и отправлен в
  Telegram; автоматический 9:16 ролик длительностью не менее 10 секунд ещё
  должен быть доказан на клиентском Node 1.
- Текущий токен используется только для тестового бота. Клиент создаст отдельный
  токен перед сдачей; значения секретов не входят в спецификацию и задачи.
- Художественный брак не означает провал системы, если клиент может
  перегенерировать или отправить правку в установленных пределах.
