# Архитектурный стандарт (Architectural Blueprint)

## 1. Физическая топология кластера
Система разделена на два физических узла, соединенных через Tailscale VPN.
*   **Node 1 (ComfyUI GPU Server):** Сервер рендера. Не принимает решений. Получает задачи от Node 2, рендерит медиа, сохраняет файлы в Shared Folder.
*   **Node 2 (The Brain - Control Server):** Сервер управления. Здесь работает мультиагентная система (Hermes Agent/MCP). Выполняет всю оркестрацию.

### Постановка задач и получение результатов: pull-модель + поллер
0. Если системный VPN Node 2 (Happ) перехватывает диапазон Tailscale,
   `scripts/tailscale_proxy.py` предоставляет локальный TCP-адрес ComfyUI и
   передаёт соединения через `tailscale nc`. Оркестратор и CLI используют
   локальный URL из `.env`, не завися от таблицы маршрутов macOS.
1.  Оркестратор (Node 2) рендерит workflow-JSON из шаблона (подстановка промптов: LTX-2.3 — позитив в `5314` Text Multiline, патчинг `5029`/`5330`/`5294`) и ставит его в очередь Node 1: `cli-anything-comfyui --url <COMFYUI_SERVER_URL> queue prompt --workflow PATH` (адрес Node 1 — из `.env`, Tailscale).
2.  **Результаты — активный поллер** (`core/poller.py`): на cron-тике Оркестратор опрашивает `cli-anything-comfyui --url <URL> --json queue history`, находит завершённые задачи по `job_id` (вшит в `filename_prefix` workflow) и переводит `media_jobs`: `generating → done` (или `error` при сбое), фиксируя имя готового файла из outputs (он же лежит в Shared Folder). Webhook-приёмник упразднён — на Node 1 работает чистый ComfyUI.

## 2. Интеграция данных и Память
Агенты не должны хранить всю информацию в контексте во избежание "Context Rot".
*   **Долговременная память:** Связка `Graphify` + Vector DB. Хранит стилистику бренда, успешные векторы контента, историю метрик и тренды.
*   **Операционная память:** Легковесная база SQLite для базовых логов выполнения, пула заготовленных постов и конфигураций ключей.
*   **Передача файлов:** Готовые медиа (mp4, png) передаются между Node 1 и Node 2 строго через сетевую папку (Shared Folder / SMB), минуя API для снижения сетевых расходов.

## 3. Иерархия Субагентов (Узел 2)
Архитектура строится на модели Supervisor/Workers (с использованием возможностей Hermes Kanban):
1.  **Оркестратор (Supervisor):** Управляет потоком задач, вызывает нужных воркеров, защищает от бесконечных циклов. Запускается по Cron.
2.  **Парсер (Trend Analyst):** Обращается к Scrape Creators API (primary) или MarkUDown MCP (fallback). Отдает чистый JSON в Graphify.
3.  **Контент-Менеджер (Planner):** Формирует контент-планы и JSON-воркфлоу для ComfyUI.
4.  **Контролер Качества (Vision Evaluator):** Принимает задания в статусе done (после поллера). Анализирует картинки (Vision). Одобряет или бракует.
5.  **SMM-Паблишер:** Дергает CLI SaaS-сервиса автопостинга, собирает метрики.
