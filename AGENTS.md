# Правила выполнения и кодирования (Harness Constraints)

## 1. Базовые правила (Mandatory)
*   Никогда не хардкодить API-ключи, пароли или пути к директориям. Использовать ТОЛЬКО `.env` файл.
*   Проект пишется на Python (версия 3.10+). Строгая типизация через `mypy` обязательна.
*   Перед каждым изменением файла проверь, не сломает ли это существующий функционал. 
*   Соблюдай принципы Harness Engineering: Agent = Model + Harness. Интеллект — в модели, безопасность и отказоустойчивость — в инфраструктуре.

## 2. Жизненный цикл Агентов (Agent Loop)
Классический бесконечный "Ralph Loop" для главного агента ЗАПРЕЩЕН во избежание сжигания токенов. 
*   **Ambient Processing:** Главный процесс (Оркестратор) должен запускаться по событиям (Cron расписание). Результаты Node 1 приходят через активный поллер истории ComfyUI (core.poller, вызывается на cron-тике), а не через входящие Webhook.
*   **Clean Context:** Каждый запуск агента должен происходить в чистом контекстном окне. Агент должен считать состояние из базы/Graphify, выполнить задачу (один шаг Kanban), записать новое состояние и полностью завершить процесс.
*   **Micro-Ralph Loop:** Допускается использование жесткого цикла перегенерации (while true) ТОЛЬКО для Контролера Качества (Evaluator), с четким условием выхода: "Брак/артефакты на изображении отсутствуют".

## 3. Управление состоянием (State Management)
*   Агент обязан синхронизировать свой прогресс с файлом `prd.json`.
*   При завершении логического блока задачи, агент должен обновить поле `passes` на `true` в файле `prd.json`.
*   Логика, подверженная сбоям (API Instagram, скрейпинг), должна быть вынесена во внешние изолированные CLI-утилиты или MCP-серверы. Агент вызывает их как системные команды (syscalls).

## 4. Фиксация состояния (State Snapshot)
*   После каждой завершённой задачи (тесты зелёные, `mypy` чистый, код работает) агент обязан без напоминаний:
    1. Обновить граф знаний: `graphify update .` (или `scripts/update_graph.sh`).
    2. Закоммитить изменения: `git add .` и `git commit -m "feat/fix/chore: [осмысленное описание]"`.
    3. Запушить в `origin main`: `git push origin main` (при первом пуше — `git push -u origin main`).
